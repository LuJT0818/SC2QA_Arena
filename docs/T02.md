# T02 部署小模型并调用推理

## 文件就三个

| 文件 | 干什么 | 行数 |
|---|---|---|
| `src/model_core.py` | 加载模型 + `generate()`。一导入就装进显存 | 55 |
| `src/model_service.py` | 把 `generate` 包成 HTTP 接口 `POST /chat` | 37 |
| `src/model_client.py` | 用 requests 调服务，打印答案和耗时 | 40 |
| `configs/model.json` | 模型路径、端口、生成长度、温度 | 7 |

关系是一条直线：`client --HTTP--> service --> model_core --> 模型`。

为什么拆成两层而不是一个文件：模型加载要 7 秒且独占 3.8GB 显存，必须放进一个常驻进程；
调用方每次跑脚本都重新加载一遍，就没法用了。这是"服务"唯一的意义。

## 怎么跑

```bash
conda activate sc2qa

python src/check_env.py        # 检查 torch/CUDA/模型文件（可选）
python src/model_core.py       # 直接生成一句，确认模型能用
python src/model_service.py    # 终端 1：起服务，监听 127.0.0.1:8008
python src/model_client.py     # 终端 2：调用
```

也可以手测：

```bash
curl http://127.0.0.1:8008/health
curl -X POST http://127.0.0.1:8008/chat -H "Content-Type: application/json" -d "{\"prompt\":\"你好\"}"
```

## 关键几行在做什么

```python
# 1. 关掉 Qwen3 的思考过程，否则 32 token 全被思考吃掉，答案是空的
TOKENIZER.apply_chat_template(messages, tokenize=False, add_generation_prompt=True, enable_thinking=False)

# 2. 只保留新生成的 token，否则答案里会重复一遍你的问题
new_ids = output[0][inputs["input_ids"].shape[1]:]

# 3. max_new_tokens 是上限不是目标，模型自己认为说完就停
max_new_tokens=max_new_tokens or CONFIG["max_new_tokens"]
```

## 实测（RTX 3060 Laptop 6GB，bf16）

| 场景 | 结果 |
|---|---|
| 模型加载 | 约 7 秒（每次启动一次） |
| 短回答（14 token） | 893 ms |
| 限 32 token | 1.1 - 2.3 s |
| 稳态速度 | 约 20 tok/s |

注意：**不要同时开两个进程加载模型**。两份额外占 7.6GB，超出 6GB 显存会走系统内存，
速度掉到原来的三分之一（实测 32 token 从 1.6s 变成 5.1s）。测速前先确认另一个进程已退出。

## 排错

| 现象 | 原因 | 处理 |
|---|---|---|
| 答案是空的 | 思考模式没关，或 `max_new_tokens` 太小 | 确认 `enable_thinking=False`，先用 256 |
| `CUDA out of memory` | 显存被别的进程占了 | 关掉另一个加载了模型的终端 / 游戏 / 浏览器硬件加速 |
| 客户端提示"调用失败 ConnectionError" | 服务没启动 | 先 `python src/model_service.py` |
| `Address already in use` | 8008 被占 | 改 `configs/model.json` 的 `port` |
| 服务秒退、没有任何输出 | 文件是空的（0 字节） | `ls -la src/*.py` 看大小 |
| `dtype` 报未知参数 | transformers 是 4.x | 把 `dtype=` 改成 `torch_dtype=` |
